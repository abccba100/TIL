## 1.  **SOP (Same-Origin Policy)**


### 1.1 기본 개념

SOP는 동일 출처 정책인데, 쉽게 말하자면 동일한 출처의 리소스만 공유 가능하도록 하는 것이다

출처의 예시는 아래와 같다  
프로토콜, 호스트, 포드가 모두 동일해야 하며 하나라도 다르다면 다른 출처(Cross-Origin)가 된다.

```jsx
프로토콜 : https
호스트 : www.google.com
포트 : 443
```

### 1.2 왜 필요할까?

CSRF와 같이 사용자가 이용하는 사이트와 공격자 사이트를 동시에 접속해 있으면 공격자 사이트에서  
사용자가 사용중인 사이트로 요청을 날린 후 민감 정보 등을 받아서와서 악용할 수 있는데  
SOP는 다른 출처의 요청에게는 리소스를 공유해주지 않기 때문에 막히게 된다.

- 왜 CSRF 공격은 막을 수 없을까?
    
    CSRF 공격은 보통 송금과 같은 요청 자체가 심각한 피해를 입히는 공격이기 때문에 위 공격과 같은 상황에서 요청을 날리는 것까지만 성공하게 되면 목적을 이루는 것이다.  
    하지만, SOP는 요청을 차단하는 것이 아닌, 요청을 받고 다른 출처의 요청일 경우 리소스 반환을 차단하는 것이기 때문에 CSRF 공격은 막을 수 없게 된다.
    

### 1.3 CORS와의 관계

SOP는 다른 출처의 리소스 공유를 막지만 CORS 설정을 통해서 접근 권한을 얻을 수 있다.

---
CORS 에러가 나도 "아 CORS 에러네 백엔드한테 설정 해달라고 해야겠다" 라고만 생각했지  
왜 CORS 에러가 나고 추가적인 설정이 필요할까 라고는 생각을 안 해봤는데 이번 기회에 알게 되서 좋았다.  
솔직히 처음에는 SOP가 굳이 필요할까 생각도 들었는데 생각보다 많은 악성 공격을 막을 것 같아서 유용한 것도 같다.
