## 1. 실행 컨텍스트


JS는 싱글 스레드라서 한 번에 하나의 코드만 실행한다. 그런데 함수는 호출될 때마다 자기만의 지역 변수, 호출된 방식, 자기가 정의된 바깥 스코프를 알아야 실행할 수 있다. 같은 함수를 두 번 호출해도 지역 변수는 서로 독립이어야 하고, 호출이 끝나면 정리되어야 한다. 이걸 만족시키려고 "호출 1회분의 실행 정보"를 한 단위로 묶어서 호출마다 새로 만드는 구조가 필요했고, 그게 실행 컨텍스트다.

### 1.1 실행 컨텍스트란?

JS엔진이 코드를 실행할 때 어떤 변수가 선언되어 있는지, `this` 는 무엇을 가리키는지, 외부 스코프에 대한 정보 등을 필요로 한다. 이 정보를 하나로 묶어놓은 객체가 실행 컨텍스트이다.

실행 컨텍스트는 함수에만 생기는 개념이 아니다. 전역 코드, 함수 코드, eval 코드 각각에 대해 생긴다. 그래서 프로그램이 시작되면 함수를 호출하지 않았어도 전역 실행 컨텍스트가 먼저 만들어진다.

### 1.2 실행 컨텍스트와 콜 스택 관계

콜 스택은 함수의 호출을 기록하고 추적하기 위해 관리한다.  
쉽게 정리하면 콜 스택은 함수 실행을 관리한다. 이 때 함수 안에 코드를 실행 시키려면 위에서 말했 듯이 여러 정보가 필요하다.  
때문에 함수를 실행하게 되면 콜 스택에는 해당 함수에 대한 실행 컨텍스트가 쌓이게 되는 것이다.

ex) A라는 함수가 있다고 가정한다면,
A 함수를 실행시키면 콜 스택에 A 함수의 실행 컨텍스트가 쌓이게 된다.  
그리고 A 함수의 실행이 종료되면 맨위 있는 A 함수의 실행 컨텍스트는 제거된다.

함수 안에서 다른 함수를 호출하면 지금 하던 일을 잠시 멈추고, 그 함수가 끝나면 원래 위치로 돌아와야 한다. 이 "돌아갈 위치"를 기억해야 하는데, 가장 안쪽에서 호출된 함수가 가장 먼저 끝나야 바깥으로 돌아갈 수 있으니 LIFO 구조인 스택이 자연스럽다. 즉 콜 스택은 함수 호출의 중첩 관계와 복귀 지점을 기록하는 구조다.

A 하나만 보면 쌓인다는 느낌이 안 드니까 중첩 호출로 보면 이렇다.

```
function A() { B(); }
function B() { console.log('B'); }
A();
```

```
[전역]
[전역, A]      <- A() 호출
[전역, A, B]   <- A 안에서 B() 호출
[전역, A]      <- B 종료, pop
[전역]         <- A 종료, pop
```

스택에는 정의된 함수가 아니라 호출 중인 함수만 올라간다. 함수가 여러 개 정의되어 있어도 나란히 호출하면 스택은 [전역, 지금 실행 중인 함수]까지만 쌓이고, 전역 컨텍스트는 프로그램이 끝날 때까지 바닥에 유지된다.

### 1.3 변수 환경 (Variable Environment)

변수 환경은 아래와 같은 정보들을 담는다.

`var` 선언, 함수 선언
실행 컨텍스트는 코드 실행 전 생성 단계에서 `var` 는 undefined로,  
함수 선언은 함수 전체로 등록되기 때문에 선언 전에 접근해도 에러가 나지 않는 것이다.  
이게 호이스팅의 원리다.

실행 컨텍스트는 코드를 바로 실행하지 않고 두 단계로 나눠서 처리한다. 먼저 생성 단계에서 코드를 훑으며 선언들을 환경에 등록하고, 그다음 실행 단계에서 위에서 아래로 코드를 실행한다. 선언이 아래에 있어도 위에서 접근할 수 있는 건 실행 전에 이미 등록이 끝나 있어서다. 아래 코드가 먼저 실행되는 게 아니다.

`var` 가 undefined인 이유는 생성 단계에서는 선언만 등록되고 할당(`= 값`)은 실행 단계에서 그 줄에 도달해야 일어나기 때문이다. 그 전까지는 값이 없는 상태로 남는다. 반면 함수 선언은 선언 자체에 본문이 포함되어 있어서 통째로 등록되고, 그래서 위에서 호출해도 정상 동작한다.

```
console.log(a); // undefined
console.log(fn()); // 'ok'
var a = 1;
function fn() { return 'ok'; }
```

- 전역 컨텍스트의 경우는 어떨까?
    
    전역 컨텍스트에는 어떤 함수 안에서 선언된 변수나 함수들이 아닌 전역 변수나 전역 함수로 선언된 정보들이 담기게 된다.
    

### 1.4 렉시컬 환경 (Lexical Environment)

렉시컬 환경은 아래와 같은 정보들을 담는다.

`let` /`const` , 외부 스코프
외부 스코프를 가져와 컨텍스트들을 체인으로 연결하여 변수 탐색 경로를 만들기 때문에 함수가 종료된 후에도 환경을 붙잡고 있을 수 있어서 클로저가 동작할 수 있다.

변수 환경과 렉시컬 환경이 둘 다 변수를 담는데 왜 나뉘어 있을까? 원래 JS에는 `var` 밖에 없었는데, ES6에서 블록 안에서만 보이는 `let`/`const` 가 추가됐다. `var` 의 동작을 바꾸면 옛날 코드가 깨지니까, 블록 단위로 변수를 담는 공간을 새로 만들었고 그게 렉시컬 환경이다.

렉시컬은 코드를 어디에 적었는지를 기준으로 한다는 뜻이다. 예제로 보면 바로 알 수 있다.

```jsx
const x = '전역';

function a() {
  console.log(x);
}

function b() {
  const x = 'b';
  a();
}

b(); // '전역'
```

a는 b 안에서 호출됐지만 'b'가 아니라 '전역'이 나온다. a가 전역에 적혀 있으니까 전역의 x를 보기 때문이다. 호출한 곳(b)에 있는 x는 보지 않는다. 변수는 어디서 불렀는지가 아니라 어디에 적혀 있는지로 찾는다. this는 이 반대라서 뒤에서 따로 본다.

클로저가 되는 이유는 안쪽 함수가 바깥 환경을 기억하고 있기 때문이다. 바깥 함수가 끝나 콜 스택에서 빠져도 그 환경은 메모리에 남아 있어서, 안쪽 함수가 바깥 변수를 계속 쓸 수 있다.

- 왜 `var` 와 `let` /`const` 스코프가 다를까?
    
    원래 `var` 는 `{ }` 이런 블록을 만나도 변수가 블록 안에서 다시 생성되지 않는다.  
    그렇기 때문에 function scope를 가지게 되는 것이고  
    `let` /`const` 는 `{ }` 이런 블록을 만나면 새 Lexical Environment가 생성되고,  
    그 블록 안의 let/const는 새 환경에 등록된다  
    그렇기 때문에 block scope를 가지게 되는 것이다.
    

`var` 는 블록이 별도 공간을 만들어주지 않아서, 블록 안에서 선언해도 블록 밖에서 보인다.

```
{
  var a = 1;
  let b = 2;
}
console.log(a); // 1
console.log(b); // ReferenceError
```

`let`/`const` 도 이름은 미리 등록되지만, 선언한 줄에 도달하기 전까지는 쓰지 못하게 막혀 있다. 이 구간이 TDZ(일시적 사각지대)이고, 여기서 쓰면 ReferenceError가 난다. 그래서 `let`/`const` 도 호이스팅은 되는 것이다.

### 1.5 This Binding

This Binding은 앞서 말한 두 환경과 성격이 조금 다르다.  
특히 렉시컬 환경에 경우에는 함수가 정의된 스코프를 기준으로 상위 스코프를 가져오지만,  
This Binding은 어떻게 호출 되었는지에 따라 결과가 달라진다.  

this는 함수를 실행시킨 대상을 가리킨다. 어떤 대상이 실행시켰는지는 함수를 부를 때 정해진다. 예제로 보면 같은 함수인데도 부르는 방식에 따라 결과가 달라진다.

```jsx
const user = {
  name: '선우',
  sayName() {
    console.log(this.name);
  }
};

user.sayName(); // '선우'  ← 점(.) 앞에 user가 있으니 this는 user

const say = user.sayName;
say(); // '선우'가 안 나옴  ← 점 앞에 아무것도 없으니 this는 user가 아님
```

함수는 같고 적혀 있는 위치도 같은데, 부른 방식만 달라서 결과가 달라졌다. 그래서 this는 적은 위치가 아니라 부를 때 정해진다고 한다. 호출할 때 점(.) 앞에 뭐가 있는지 보면 된다.   `call`/`apply`/`bind` 로 this를 직접 정해줄 수도 있다.

화살표 함수는 This Binding을 만들지 않고 상위 컨텍스트의 This Binding을 사용하기 때문에  
우리가 아는 화살표 함수와 `this` 의 관계가 만들어지는 것이다.

화살표 함수는 콜백 안에서 this가 바뀌는 문제를 없애려고 생겼다. 자기만의 this를 만들지 않고 바깥의 this를 그대로 쓴다. React 클래스 컴포넌트에서 핸들러를 화살표 함수로 쓰던 이유도 이거다.
