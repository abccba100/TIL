## 1. 등장 배경


### 1.1 멀티 스레드와 싱글 스레드

스레드는 실제 일(이벤트 처리 등)을 처리하는 일꾼 같은 것인데,  
프로그래밍 언어 마다 멀티 스레드인지, 싱글 스레드인지 나뉘게 된다.

멀티 스레드는 여러 작업을 여러 개의 스레드에서 병렬로 작업을 처리할 수 있다는 장점이 존재하지만,  
동시성 문제나 무겁다는 뚜렷한 단점이 존재한다.

반면, 싱글 스레드는 기본적으로 멀티 스레드처럼 여러 작업을 병렬로 처리할 수 있는 없지만,  
동시성 문제가 없고 가볍게 동작한다는 장점이 존재한다.

### 1.2 뭐가 문제일까

JavaScript는 싱글 스레드 언어이기 때문에 한 번에 하나의 작업만 처리할 수 있지만,  
웹에서는 사용자 동작에 따른 여러 이벤트, 네트워크 요청 등 시간이 걸리는 작업들이 존재한다.

사용자가 웹 사이트에 접속하여 상품 조회를 했다고 가정해본다면,  
JS는 서버에서 데이터가 올 때까지 기다리느라 사용자의 동작(클릭, 스크롤 등)이나 기능(함수 등)들을 처리하지 못하고 계속 기다리는 상황이 발생하게 된다.

## 2. 이벤트 루프


### 2.1 이벤트 루프란

이벤트 루프는 싱글 스레드 기반인 JS를 멀티 스레드로 돌려 작업할 수 있게 하고,  
여러 작업 중 어떤 작업을 먼저 처리할지도 결정한다.

### 2.2 이벤트 루프 흐름

이벤트 루프는 Call stack, Callback Queue, WebAPIs로 이루어진다.

Call stack에서는 실제 작업들이 실행되며, `setTimeout` 과 같이 비동기 처리가 필요한 작업은 WebAPIs 넘어간 후 작업이 완료될 때 까지 대기하고, WebAPIs에서 작업이 끝나면 Callback Queue로 넘어가서 Call stack이 완전히 비워질 때까지 기다린 후 넘어간다.

### 2.3 Call stack

모든 작업들이 처리되는 곳으로 동기 작업은 Call stack에서 바로 처리되며,  
비동기적 작업 또한 최종적으로는 Call stack으로 넘어와서 처리된다.

### 2.4 WebAPIs

비동기적 작업들이 처리되는 곳으로 WebAPIs는 멀티 스레드로 구성되어 있다.  
넘어온 비동기적 작업들을 DOM, Timer API, XMLHttpRequest 등 알맞는 스레드에서 작업을 완료하도록 한다.

### 2.5 **Callback Queue**

Callback Queue는 Task Queue와 Microtask Queue로 나뉘는데,  
Task Queue는 `setTimeout`, `setInterval`, `fetch`, `addEventListener` 같은 비동기 작업이 대기 하는 큐이고,  
Microtask Queue는 `romise.then`, `process.nextTick`, `MutationObserver` 같은 우선순위가 높은 비동기 작업이 대기 하는 큐이다.  
그렇기 때문에 Call stack이 비었을 때 Microtask Queue에 있는 작업이 우선적으로 처리되며, Microtask Queue가 모두 비워졌을 때 Task Queue에서 대기 중인 작업들이 처리된다.
