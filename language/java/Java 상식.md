## 1. Java 상식

### 1.1 JVM

java 언어로 쓰인 코드를 기계어로 번역할 때  
java → 바이트 코드 → 기계어 순으로 번역한다.  

이때 바이트 코드에서 기계어로 번역해주는 역할을 하는 게 JVM이다

단, JVM은 한 가지 방식으로만 바이트 코드를 기계어로 번역하지 않는다.  
한 줄씩 번역하는 인터프리터 방식과 JIT 컴파일러 방식을 혼합해서 사용한다.

- JIT 컴파일러(Just-In-Time Compiler) 방식이란?
    
    같은 코드가 반복되는 걸 감지하면 그 부분을 번역한 후에 통째로 캐싱해두고 이후에는 매번 번역하지 않고 캐싱해둔 것을 사용해서 훨씬 빠르다.
    

JVM은 인터프리터 방식을 사용하니 초기 실행 속도가 빠르고 JIT 컴파일러 방식도 사용하니 장기 실행 성능까지 모두 챙겼다.

JVM 내부는 크게 3가지로 나누어진다.

1. **클래스 로더**
    
    .class 파일(바이트 코드)를 찾아서 JVM 메모리에 올려준다.  
    더 쉽게 말하자면 요리(코드 실행)을 하려고 할 때 재료(.class 파일)이 필요한데 이 재료를 찾아서 도마(메모리)에 올려주는 역할이다.
    
2. **런타임 데이터 영역**
    
    클래스 로더가 올려놓은 .class 파일들을 담아두는 메모리 영역으로 대표적으로 2가지만 알아보자
    
    1. **힙 영역**
        
        new로 생성한 객체들이 실제로 저장되는 곳으로 나중에 안 쓰는 객체는 GC(가비지 컬렉터)가 알아서 치운다.
        
    2. **스택 영역**
        
        메서드를 호출할 때 마다 생기는 임시의 공간으로 지역 변수, 계산 중인 값 들이 여기에 잠깐 저장 되었다가 메서드가 끝나면 사라진다.
        
3. **실행 엔진**
    
    메모리에 올라온 바이크 코드를 기계어로 바꾸는 녀석으로 여기에 아까 말한 인터프리터랑 JIT 컴파일러가 들어있다.  
    아까 힙 영역에 있던 GC도 실행 엔진 쪽에 속한다.
    

결론적으로 흐름은 클래스 로더가 파일을 메모리로 가져오고  
런타임 데이터 영역에 저장이 되고  
실행 엔진이 그걸 읽고 기계어로 바꿔서 실행한다.

### 1.2 JRE

Java에서 자주 사용되는 라이브러리 같은 도구들이 담겨 있는 걸로 JVM도 JRE 안에 담겨 있고,
System.out.println() 같은 기능을 별도의 설정 없이 사용할 수 있는 것도 JRE 라는 실행 환경 덕분이다.

### 1.3 JDK

JDK도 자바 애플리케이션(Java 프로그램)을 개발할 때 필요한 도구들이 담겨 있는 것이다.
하지만 JRE 보다 더 큰 개념으로 JDK 안에 JRE가 들어있고, java → 바이트 코드로 해석해주는
컴파일러(javac)도 JDK 안에 들어있다.
