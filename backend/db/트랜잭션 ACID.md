## 1. 트랜잭션


### 1.1 트랜잭션이란?

트랜잭션은 여러 개의 DB 작업을 하나의 논리적 단위로 묶은 것을 말한다.
예를 들어서 A가 B에게 계좌이체를 한다고 가정하면
’A 계좌에서 돈이 빠져나간다’ 와 ‘B 계좌에 돈이 들어간다’ 라는 두 작업은 묶여서 한 번에 처리되기 때문에 이런 작업 묶음을 트랜잭션이라고 부른다.

- 왜 작업을 묶을까?
    
    아래에서 자세히 나오지만, 트랜잭션은 ACID 성질을 가지는데
    이 성질이 지켜야지 DB의 작업들이 안전하게 진행되기 때문에 트랜잭션이라는 단위로 작업을 묶고 ACID 성질에 따라 처리되게 된다.
    

## 2. ACID


### 2.1 원자성 (Atomicity)

원자성은 작업들이 전부 성공하거나 전부 실패하는 것을 말한다.
더 구체적으로 설명하자면 트랜잭션 단위로 묶인 여러 작업들이 모두 성공하거나 모두 실패해야 한다는 성질이다.

- 왜 모두 성공하거나 모두 실패해야 할까?
    
    위에서 말했던 A가 B에게 계좌이체를 하는 상황을 다시 떠올려봤을 때,
    원자성이라는 성질이 적용 되지 않는다면 아래와 같은 상황이 생겼을 때 문제가 생긴다.
    설명을 편하게 하기 위해서 ’A 계좌에서 돈이 빠져나간다’는 A 작업, ‘B 계좌에 돈이 들어간다’는 B 작업이라고 부를 때,
    A 작업은 성공했지만 B 작업은 실패하는 경우가 생겼을 때, 원자성이 적용되면 모두 성공하거나 실패해야 하기 때문에 앞에서 이미 성공한 A 작업까지 실패한 것으로 처리하게 된다.
    하지만 원자성 성질이 적용되지 않으면 A 작업은 성공, B 작업은 실패가 그대로 적용되게 된다.
    이렇게 되면 A 계좌에서 돈은 빠졌는데 B 계좌에는 변화가 없는 상황이 생긴다. 이런 문제를 방지하기 위해서 트랜잭션은 원자성이라는 성질을 가지게 된다.
    

### 2.2 일관성 (Consistency)

일관성은 트랜잭션이 끝났을 때 규칙(제약 조건, 무결성 등)을 만족해야 한다는 것을 말한다.
만약에 트랜잭션이 끝나고 규칙에 부합하지 않는다면 해당 트랜잭션을 실패처리 하여 데이터를 롤백 시킨다.

### 2.3 격리성 (Isolation)

격리성은 여러 트랜잭션들이 동시에 실행될 때 서로에게 간섭하지 않고 혼자만 실행되는 것처럼 동작하는 것을 말한다.

- 왜 혼자만 실행되는 것처럼 동작해야 할까?
    
    만약 여러 트랜잭션들이 실행될  때 각각 혼자만 실행되는 것처럼 동작하지 않고 서로에게 간섭을 하게 되면 아래와 같은 문제가 생길 수 있다.
    위에서 말했던 A, B 작업을 하나의 트랜잭션이라고 하고 A의 계좌에 2,000원이 들어오는 작업 C를 또 다른 하나의 트랜잭션이라고 가정했을 때
    (A의 잔고는 5,000원이며 B에게 계좌이체 하는 금액은 3,000원이다.)
    A 작업이 실행된 끝나기 전에 C 작업이 실행되었다고 해보자 이러면 A 작업이 먼저 끝나 A의 잔고는 2,000원이 되었는데 C 작업이 실행 될 시점에는 A의 잔고를 5,000원으로 읽었기 때문에 5,000 + 2,000이 되어 A 잔고는 7,000원이 되게 된다.
    이런 경우에는 돈이 생겨나고 반대의 경우에도 돈이 사라지는 매우 심각한 버그들을 초래하고 사용자와 개발자 모두 데이터를 신뢰할 수 없는 상황이 되기 때문에 개인적으로 격리성은 매우 중요한 성질이라고 생각한다.

- 격리성에도 레벨이 존재한다
    
    이번에 트랜잭션 ACID 찾아보다가 알게 된 건데 격리성에도 레벨이 존재하고 개발자가 설정할 수 있다.  
    단계 별 특징이 있지만, 자세하게 설명하자면  
    레벨 0은 commit 되지 않은 작업 중인 데이터를 읽을 수 있는 단계이다.  
    레벨 1은 commit된 데이터만 읽는 단계이다.  
    레벨 2는 데이터를 읽고 있는 중에 데이터를 수정할 수는 없지만 추가로 넣을 수 이는 단계이다.  
    레벨 3은 데이터를 읽고 있는 중에 데이터 수정 뿐만 아니라 추가로 넣을 수도 없는 단계이다.  


### 2.4 지속성 (Durability)

트랜잭션이 커밋된 후에는 결과가 영구적으로 보존되어야 한다는 것을 말한다.
보통 DB는 데이터를 디스크에 기록하여 지속성을 보장한다.
