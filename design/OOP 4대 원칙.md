## 1. 객체 지향 4대 원칙


### 1.1 추상화 (**Abstraction)**

추상화는 아래와 같은 생각에서 출발 되었다고 생각한다.

”현실에 있는 대상을 코드로 옮긴다고 했을 때 현실의 대상의 정보, 동작 등이 필요한데,  
부품이 3만 개인 내연 자동차를 코드로 옮긴다고 했을 때 3만개의 정보를 만들어서 정보를 입력해야 할까?”

답은 당연하게도 아니다이다  
어차피 자동차의 중요한 정보들은 색상, 가격, 제조사 등이기 때문에 굳이 불필요하고 자잘한 3만개의 정보를 모두 포함하지 않고 **핵심적인 정보만 간결하게 추출할 것이다.**

이렇게 현실에 존재하는 사물이 가진 속성 중에 필요한 것만 추출하여 코드로 옮기는 것을 추상화라고 한다.

### 1.2 캡슐화 (**Encapsulation)**

캡슐화는 속성과 동작을 클래스로 묶어 만드는 것을 말한다.

### 1.4 다형성 (Polymorphism)

다형성은 아래와 같은 생각에서 출발되었다고 생각한다.

"Dog와 Cat이 둘 다 Animal을 상속받았는데, 이 둘을 매번 따로따로 다뤄야 할까? 하나로 묶어서 다루면서도 각자 다르게 동작하게 만들 수는 없을까?"

답은 가능하다이다.

부모 타입(Animal) 변수에 자식 객체(Dog, Cat)를 담아두면, 겉으로는 같은 타입으로 취급하면서도 실제로는 각 객체가 가진 고유한 동작이 실행되도록 만들 수 있다.

아래 예시를 보면 다형성에 대해서 이해하기 쉽다.

```java
class Animal {
    void sound() {
        System.out.println("동물이 소리를 낸다");
    }
}

class Dog extends Animal {
    void sound() {
        System.out.println("멍멍");
    }
}

class Cat extends Animal {
    void sound() {
        System.out.println("야옹");
    }
}
```

```java
Animal a1 = new Dog();
Animal a2 = new Cat();

a1.sound(); // 멍멍
a2.sound(); // 야옹
```

a1과 a2는 둘 다 Animal 타입으로 선언되어 있지만, 실제로 담긴 객체가 Dog냐 Cat이냐에 따라 sound()의 결과가 달라진다. 즉 겉모습(선언 타입)은 같아도 속(실제 객체)이 다르면 다르게 동작하는 것이다.

이 성질 덕분에 서로 다른 자식 객체들을 하나의 부모 타입으로 묶어서 관리할 수 있다.

```java
Animal[] animals = { new Dog(), new Cat() };

for (Animal a : animals) {
    a.sound(); // 각 객체의 실제 타입에 맞게 알아서 실행된다
}
```

이렇게 타입 하나로 묶어서 처리하면서도, 실행되는 순간에는 각 객체의 실제 동작이 실행되는 것, 이것이 다형성이다.
