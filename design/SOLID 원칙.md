## 1. SOLID 원칙이란?


### 1.1 SOLID 원칙 기본 개념

SOLID 설계 원칙은 표준화 작업이나 아키텍처 설계까지 다양하게 적용되는 개념이기 때문에 자세히 알고 있어야 한다.

- SOLID 원칙을 왜 적용해야 할까?
    
    SOLID 객체 지향 원칙을 적용하면 확장, 유지 보수 관리, 복잡성 제거 등을 통해 리팩토링에 소요되는 시간을 줄여 개발 생산성을 높일 수 있다.
    

### 1.2 단일 책임 원칙 (Single Responsibility Principle)

단일 책임 원칙 클래스(객체)가 단 하나의 책임(기능)만 가져야 한다는 원칙이다.

- 만약 단일 책임 원칙이 지켜지지 않으면 어떻게 될까?
    
    단일 책임 원칙이 지켜지지 않는다면,  
    기능 하나를 수정하려고 했을 때 수정해야할 코드가 많아질 수 있다. 원래는 A를 변경하려고 했는데 B까지 변경하게 되고 이어서 C까지 변경하게 되는 등 하나의 클래스(객체)가 여러 책임(기능)을 담당하게 된다면 유지보수성이 심하게 떨어질 수 있다.
    

### 1.3 개방 폐쇄 원칙 (Open Closed Principle)

개방 폐쇄 원칙은 ‘클래스는 확장에 열려 있어야 하며, 수정에는 닫혀 있어야 한다’를 의미한다.

처음 이 말을 들었을 때는 이게 진짜 무슨 말인가 했는데,  
진짜 쉽게 말하면 개방 폐쇄 원칙은 새로운 기능을 추가한다고 했을 때, 기존 코드는 건드리지 않고 새 코드를 작성해서 기능을 확장한다는 원칙이다.  
정리하면, 수정하지 않고 새롭게 작성해서 확장을 한다는 것이다. 그러면 다시 아래 말을 보면 이해가 될 거다.  
‘클래스는 확장에 열려 있어야 하며, 수정에는 닫혀 있어야 한다’

### 1.4 리스코프 치환 법칙 (Liskov Substitution Principle)

리스코프 치환 법칙은 ‘서브 타입은 언제나 기반(부모) 타입으로 교체할 수 있어야 한다’를 의미한다.

쉽게 말하자면, 리스코프 치환 법칙은 다형성의 특징을 이용하기 위해서 기반(부모) 클래스 타입으로 객체를 선언한 후에 자식 클래스의 인스턴스를 받으면 업스캐딩된 상태에서 부모의 메서드를 사용해도 동작이 의도된 대로 흘러가야 한다는 것을 말한다.

따라서 상위 클래스의 메서드를 바꿔치기 할 수 있는 오버라이딩을 할 때 리스코프 치환 법칙을 생각하면서 조심스럽게 사용해야 한다.

### 1.5 인터페이스 분리 원칙 (Interface Segregation Principle)

인터페이스 분리 원칙은 말 그대로 인터페이스를 각각 사용에 맞게 잘 분리해야 한다는 원칙이다.

단일 책임 원칙이 클래스의 단일 책임을 말한다면, 인터페이스 분리 원칙은 인터페이스의 단일 책임을 말한다.

쉽게 말하면, 하나의 인터페이스를 여러 클래스가 상속 받아서 사용할 수 있으니까 클래스들이 인터페이스를 상속 받았을 때 필요 없는 기능들을 받는 경우를 줄이기 위해서 인터페이스를 분리하는 것이다.

### 1.6 의존 역전 원칙 (Dependency Inversion Principle)

의존 역전 원칙은 어떤 클래스를 참조하려고 할 때, 그 클래스를 직접 참조하는 게 아닌 그 대상의 상위 요소(추상 클래스나 인터페이스)를 참조하는 원칙이다.

- 왜 상위 요소와 의존 관계를 맺을까?
    
    의존 관계를 맺을 때 변하기 쉽거나 자주 변하는 구현 클래스 대신 변하기 어렵거나 거의 변화가 없는 추상 클래스, 인터페이스와 의존 관계를 맺는다.
